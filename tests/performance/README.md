# Performance profile (TEST-03)

k6 scenarios live here and run through the Compose `performance` profile against the real backend and main `itms` database. Nothing in this folder changes frontend/backend source or production migrations. Keep successful fixtures for UI trials; do not truncate tables/reset sequences. No k6 process runs during normal startup.

## Run

```sh
docker compose --profile performance run --rm k6 run /scripts/read-scenario.js
docker compose --profile performance run --rm k6 run /scripts/write-scenario.js
```

Each run writes a self-contained HTML report with an end-of-run UTC timestamp to `results/k6-<scenario>_<YYYYMMDD-HHMMSS>Z.html` (generated by `handleSummary` in [report.js](report.js); this k6 build has no `--report-file`). A compact text summary goes to stdout — redirect it to a log file for evidence.

- `read-scenario.js` — list default / keyword search / status filter / status+department filter / pagination / detail by id. `setup()` prepares the dataset through the API (default 8 DRAFT + 8 PENDING + 8 APPROVED, marker `K6RD-…`) outside measured time.
- `write-scenario.js` — Create Draft → Submit → Approve per iteration, each iteration on its own request with API-returned versions (marker family `K6WR-…`); successful fixtures are kept.

## Configuration (test-side env, defaults in scripts)

| Env          | Default                                | Meaning                                |
| ------------ | -------------------------------------- | -------------------------------------- |
| `BASE_URL`   | `http://backend:8080` (set by Compose) | Backend base URL                       |
| `VUS`        | `10`                                   | Virtual users                          |
| `DURATION`   | `1m`                                   | Measured duration per run              |
| `P95_MS`     | `500`                                  | p95 threshold (ms)                     |
| `FAIL_RATE`  | `0.01`                                 | failed-request threshold               |
| `CHECK_RATE` | `0.99`                                 | workflow-assertion pass-rate threshold |
| `SETUP_EACH` | `8`                                    | Read setup: requests per status        |
| `SLEEP`      | `1`                                    | Iteration pacing (seconds)             |

Example override: `docker compose --profile performance run --rm -e VUS=5 -e DURATION=30s k6 run /scripts/read-scenario.js`

Thresholds filter on `{scenario:default}` so `setup()` traffic is never counted in pass/fail. k6 exits non-zero when a threshold is crossed.
